calshare は匿名・ログイン不要でカレンダー予定を発行するため、フィッシングとカレンダースパムの標的になりやすい（concept §09）。このスキルは docs/design.md §9 の対策が「実際にそのとおり実装されているか」を、判定と根拠のペアで報告する。判定を放棄せず、未実装の項目は「どのPRで実装予定か」まで言い切る。

## 対象の確定

依頼の言い方から対象を決める。

- 「このPR」「今の変更」→ `git diff main...HEAD`（または指定ブランチ）の差分ファイルに絞る。
- 「ブランチ全体」「〜ブランチを見て」→ そのブランチの `main` との差分ファイル全体。
- 「セキュリティ監査して」のように対象指定が無い → リポジトリ全体（`src/` が存在すればそこを対象、無ければ全項目が未実装である旨だけ報告する）。

## 手順

1. **チェックリストを開く**: `references/checklist.md` に §9 の全項目が「何を確認するか / どのファイル / 合格の証拠 / 実装PR」で並んでいる。対象に含まれるファイルに関係する行だけを抜き出す。
2. **各項目を判定する**: 該当ファイルを実際に開いて確認する。
   - **合格**: 該当コードがあり、チェックリストの「合格の証拠」を満たす。ファイルと行を引用する。
   - **不合格**: 該当コードはあるが基準を満たさない（例: `innerHTML` を使っている、CORSヘッダが付いている）。重大度と修正案を添える。
   - **未実装**: 該当ファイルがまだ存在しない。チェックリストの「実装PR」列をそのまま「T8で実装予定」のように報告する。`src/` 自体が無ければ全項目がこれになる。
   - **該当なし**: 対象範囲（例: 特定のPRの差分）にその項目が関係しない。
3. **可能なら再現する**: 不合格・未実装以外の項目のうち、ユニットテストで再現できるもの（XSS注入・URL置換・レート制限の境界・Origin検証）は簡単なテストを書いて実行し、結果を証拠に加える。既存テストで確認できるなら新規に書かず、その場で `npm test` 相当を実行して green を確認する。
4. **組み込みの `/security-review` を使えるか確認する**: 対象が git 差分を持つ（PR・ブランチ）場合は `/security-review` を併用する。出力された指摘を、ファイル・行・観点が重複するものは1件に統合し、`/security-review` 独自の指摘（このチェックリストに無い観点）は「追加の指摘」として別枠で残す。差分が無い（リポジトリ全体の棚卸し）場合は併用しない。
5. **ID・トークン・ics・プリフィルなど§9本文に無い項目**は `references/checklist.md` の「補足」節を見る（§4.2・§3.3・§7.2・§5.8 に対応）。
6. **GitHub Actions・runbook側の観点**（inputs注入・permissions等）は ops-audit スキルの領域なので深追いせず、必要なら「ops-audit も参照」と一言添える。

## 出力テンプレート

```
## security-audit: <対象>

### 総合判定
マージ可 / 修正後に可 / 不可

### 判定サマリ
| 項目 | 判定 |
|---|---|
| 9.1 XSS | 合格 |
| 9.3 レート制限 | 未実装（T6/T7で実装予定） |
| 9.8 CORS/CSRF | 不合格 |

### 不合格の詳細
- **[高] 9.8 CORS/CSRF**: `src/server/app.ts:23` で `cors()` を全ルートに適用しており `/api/*` にも `Access-Control-Allow-Origin: *` が付く。
  修正案: `/api/*` のサブアプリだけ `cors()` を外す。

### 未実装の項目（実装予定PR）
- 9.3 レート制限: T6（アダプタ）/ T7（middleware）
- 9.4 通報Webhook: T12

### 追加した・提案するテスト
- `test/integration/server/sameOrigin.test.ts` に「別オリジンのPOSTが403」のケースを追加（提案。T7で実装時に含める）

### オーナーの判断事項
無し

### 次のアクション
- 誰が: 実装担当。何を: 9.8 CORS/CSRF の修正案を適用してから再度このスキルで確認する
```

「合格」の項目も根拠（ファイル:行）を1行添える。判定だけ書いて根拠を省略すると、オーナーが再確認する手間が発生し「土台を作る」という目的に反する。
