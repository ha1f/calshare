# go-live-check: スクリプトが担わない判断の手順

`scripts/go-live-check.mjs` が機械的に出す結果だけでは、公開可否の最終判定はできない。
このファイルは、スクリプトの出力を受けてこのセッションが行う 2 つの判断の手順を書く。

## 0. H 番号 → スクリプトの key → 確認方法の対応表

`owner help wanted` Issue（design.md §13 の H1〜H14）とスクリプトの項目 key は別の切り口の一覧なので、
同じ H を二重に数えたり、対応が無いのに「スクリプトに無い」と誤認したりしないよう、先にこの表で
突き合わせる。**同じ H は報告でも1行にまとめ、根拠にスクリプトの key と Issue 番号を併記する。**

| H番号                                | スクリプトの key                                                          | 確認方法                                                                                                                                                                                                 |
| ------------------------------------ | ------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| H1（サービス名・ドメイン）           | `undecided:1`, `wrangler:origin`                                          | スクリプト出力を見る                                                                                                                                                                                     |
| H2（Workers Paid 契約）              | `undecided:7`                                                             | スクリプト出力を見る                                                                                                                                                                                     |
| H3（DNS移管・カスタムドメイン）      | `wrangler:workers_dev`, `wrangler:routes`                                 | スクリプト出力を見る                                                                                                                                                                                     |

## 1. `owner help wanted` Issue 本文を読んで公開をブロックするか判断する

スクリプトの `issues` 項目は件数と `#番号 タイトル` の一覧しか出さない。次を行う。

```sh
gh issue list --label "owner help wanted" --state open --json number,title,url
gh issue view <番号>
```

各 Issue の本文（`owner-task` スキルの雛形に沿っていれば「オーナーに残る作業（最小）」
「判断が必要な事項」の 2 節）を読み、次の規則でブロッカーか推奨事項かを分ける。
design.md §13 の「ブロックするタスク」列は**実装タスク（T19）の依存関係を表す列であり、
公開可否そのものを表す列ではない**ことに注意する（矛盾を避けるための前提）。

1. **スクリプトが blocker とした項目は、Issue 本文を理由に推奨事項へ格下げしない。** 格下げできるのは、
   実物（Cloudflare ダッシュボード、GitHub Secrets/Variables 等）を確認して実際に解消済みと分かった
   ときだけ。
2. **Issue 精査で新たにブロッカーへ格上げしてよいのは**、design.md §13 の「ブロックするタスク」列に
   `T19` を含む H 番号のうち、上記「0.」の対応表で**スクリプトに対応項目が無いもの**（H6・H8）だけ。
   スクリプトに対応項目がある H（H1〜H5・H7・H10）は、スクリプトの判定をそのまま使う。
3. `T19` を含まない H（H9・H11〜H14）は「ブロックするタスク＝—」だが、**H13・H14 は design.md の
   備考に「公開前に設定するのが望ましい」「公開前と LINE のメジャー更新時」とあるため、これらと H10
   （法的文言）は公開前に必要な項目として扱う**（H10 はスクリプトが `legal:*` で既にブロッカー化して
   いる）。H13・H14 は Issue 本文を読んで、公開前に済ませるべきかを個別に判断する。H11・H12（継続運用）
   と H9（デプロイ承認そのもの）は「公開後・運用時の作業」として確認できた扱いにする。
4. **REPORT_WEBHOOK_URL（H7）の食い違いに注意する**: design.md §13 は H7 の「ブロックするタスク」を
   `T19` としているが、`docs/runbooks/provisioning.md` は「任意」と書き、スクリプトも `warn` 止まり
   （`secret:REPORT_WEBHOOK_URL`）にしている。この食い違いはこのセッションが独自に優先順位を決めず、
   「オーナーの判断事項」として report に出す（design.md に合わせて必須にするか、provisioning.md に
   合わせて任意のままにするか）。
5. 「完全に自動化できた」とだけ書かれていて実は未クローズの Issue があれば、`owner-task` スキルの
   手順3（クローズ）を提案する。

## 2. design.md §14.2 未決事項が「決まったか」を確認する

スクリプトの `undecided:*` 項目は、`docs/design.md` §14.2 の番号付きリストをそのまま抽出したもので、
「まだ書かれている = まだ決まっていない」という前提で blocker/warn を割り当てている。したがって
このセッションが行うのは次の 2 点だけでよい。

1. `docs/design.md` の §14.2 を実際に開き、各項目の文面が「決定した」内容に書き換わっているか、
   あるいは決定内容が別セクション（例: §9 に追記される契約情報、§1 に追記されるサービス名）に
   反映されているかを確認する。書き換わっていれば、その番号はスクリプト側でも自然に消える
   （抽出元がもう箇条書きの形で残っていないため）。
2. スクリプトが `undecided:1`（サービス名・ドメイン）と `undecided:7`（Workers Paid 契約承認）を
   ブロッカーにしているのは、design.md §13 の H1・H2 が T19（本番デプロイ）を直接ブロックすると
   明記されているため（`scripts/go-live-check.mjs` の `UNDECIDED_ITEM_BLOCKING_INDEXES`）。
   design.md の §12 タスク表やこのブロック指定自体を変更した場合は、スクリプト側の定数も
   合わせて見直す必要がある（このファイルとスクリプトのコメントの両方を更新する）。

## 判定を報告する前のチェックリスト

- [ ] `node .claude/skills/go-live-check/scripts/go-live-check.mjs` を実行した
- [ ] open な `owner help wanted` Issue をすべて `gh issue view` で読んだ
- [ ] `docs/design.md` §14.2 を開き、スクリプトが抽出した項目のうち決定済みのものを洗い出した
- [ ] 上記 2 点を踏まえて、スクリプト単体の判定から変える必要があるか判断した（変えた場合は理由を明記する）
