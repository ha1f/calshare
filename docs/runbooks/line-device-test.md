# LINE 実機での動作確認（H14）

## 目的

LINE トークに貼った詳細ページ URL が、LINE 内蔵ブラウザ経由でもカレンダー追加・ics 取り込み
まで完走することを、iOS / Android それぞれの実機で確認する。`openExternalBrowser=1`
（design.md §6.6）の効き方は LINE のバージョン依存で要検証のため、コードでは確認できない。

## 自動化されていること

なし。実機と LINE アカウントが要る目視確認のみで、自動化はできない
（design.md §13 の H14 そのものがこの理由で人手作業になっている）。
このドキュメントはチェックリストと結果の記録欄を提供する。

## チェックリスト（iOS・Android で同じ手順を実施する）

| # | 手順 | 期待結果 |
|---|---|---|
| 1 | LINE トーク（自分宛てのメモ、または検証用の 1:1 トーク）に詳細ページ URL を貼って送信する | 数秒後に OGP カード（タイトル画像・日時・サービス名）が表示される |
| 2 | 送信したカードをタップする | LINE 内蔵ブラウザで詳細ページが開き、レイアウトが崩れずに表示される |
| 3 | 詳細ページの「Google カレンダーに追加」ボタンをタップする | `openExternalBrowser=1` 付きの URL で外部ブラウザ（iOS は Safari、Android は既定ブラウザ）が開き、Google カレンダーの予定作成画面が表示される |
| 4 | 詳細ページの「その他（ics をダウンロード）」ボタンをタップする | 同様に外部ブラウザで開き、ics ファイルのダウンロードと、端末のカレンダーアプリへの取り込み導線（共有シート・ダウンロード後の通知など）が表示される |
| 5 | 手順 4 の ics を実際に取り込む | 端末の標準カレンダーアプリに予定が追加される |
| 6 | 手順 3・4 でボタンをタップしても外部ブラウザに切り替わらない場合を想定し、内蔵ブラウザのまま画面を確認する | 「うまく開けないときは右上メニューの『他のアプリで開く』を使ってください」の案内バナーが表示されている（design.md §6.6） |

- 各セルは OK / NG で記録する。NG の場合はメモに具体的な症状（ボタンが反応しない、外部ブラウザが

- iOS・Android それぞれ最低 1 行以上記録する。LINE のメジャーバージョンアップ後は再実施する

## 判断が必要な事項

- 手順 3・4 のいずれかが継続して NG（`openExternalBrowser=1` が効かない）と分かった場合、
  次のどちらで対応するかはオーナー判断になる。
  1. **現状維持**: 案内バナー（手順 6）を主な回避策として残す。実装済みの設計を変えない
     （design.md §6.6 は元々これを前提にしている）。
  2. **共有 URL 自体に `openExternalBrowser=1` を付ける**（design.md §14.2 の未決事項 9）。
     「LINE で送る」が生成する URL 自体にパラメータを付け、LINE トークから開いた時点で
     詳細ページごと外部ブラウザに切り替える。ics の問題を根本的に避けられるが、共有 URL が
     長くなる・この対応も同じく実機確認が前提になる、という代償がある。
- 手順 1（OGP カード表示）が NG の場合は本ドキュメントの対象外（design.md §2.5 の OGP 生成側の
  問題）。`docs/runbooks/fonts.md` や satori/resvg の実装側を確認する。

## 失敗したときの見方

- カードが表示されない（手順 1 NG）: OGP 画像の生成に失敗している可能性が高い。
  詳細ページの `og:image` を直接開いて画像が返るか確認する。
- ボタンをタップしても何も起きない（手順 3・4 NG、バナーも出ない）: `Line/` UA 判定が
  効いていない可能性がある。詳細ページの HTML を確認し、ボタンの `href` に
  `openExternalBrowser=1` が付与されているか見る（design.md §6.6 のクライアント側 JS の
  UA 判定に問題がある場合はコード側の修正が必要で、本ランブックの対象外）。
- ics が取り込めない（手順 5 NG）: ics ファイル自体の内容を PC 等で開いて検証する
  （design.md §7.2）。LINE 経由固有の問題か、ics 生成側の問題かを切り分ける。
