# 規約類の承認手順（H10）

## 目的

利用規約・プライバシーポリシー・通報ポリシーの雛形（[docs/legal/terms.md](../legal/terms.md)、[docs/legal/privacy.md](../legal/privacy.md)、[docs/legal/report-policy.md](../legal/report-policy.md)）を、実際にサービスへ掲載できる状態にするための手順です。

**本書および上記3文書はドラフトであり、法的助言ではありません。** 内容はdocs/design.md §3・§7・§9に記載された本サービスの実装仕様に基づいて作成していますが、公開前に必ずオーナー自身が内容を確認し、必要に応じて弁護士等の専門家に相談してください。

## 自動化されていること

- 3文書は、サービスの実態（ログイン不要・無料・保持期限・編集方式・ログの扱い・通報の仕組み・Cloudflareでのホスティング・広告なし・サポート窓口なし）に基づいたドラフトとして作成済みです。
- 各文書冒頭の「施行日」「運営者」欄、[docs/legal/terms.md](../legal/terms.md) 第17条の管轄裁判所、末尾の変更履歴表は、オーナーが決めた値を記入する前提のプレースホルダとして用意済みです。記入は次節のとおり `scripts/legal/apply-legal-values.mjs` で一括反映できます。
- フォーマット検査スクリプト `scripts/legal/checkLegalDocs.mjs` が、次を機械的に検査します。今後の改定でも同じスクリプトで確認できます。
  - 3ファイルすべてが存在すること
  - 「施行日: 」「運営者: 」の行があること
  - 「## 第N条」の条番号が1から連番になっていること（欠番・重複を検出）
  - 末尾に「## 変更履歴」の見出しと、「日付」「変更内容」の列を持つ表があること
  - 未記入のプレースホルダ（「（オーナーが記入…）」「（記入）」）が残っていないこと。既定では警告として一覧表示するのみですが、`--strict` を付けると1件でも残っていれば終了コード1になります（掲載前の最終確認用）
  - このスクリプトは**内容（文言そのものの妥当性・法的な正しさ）は検査しません**。内容の確認は次節のオーナー作業に委ねます。

## オーナーが行う最小の作業

1. 施行日・運営者表記・管轄裁判所の3つの値を決める（「判断が必要な事項」を参照）。
2. 次のコマンドで3文書に一括反映する。まず `--dry-run` で変更予定の行を確認してから、`--dry-run` を外して実行する。

   ```sh
   node scripts/legal/apply-legal-values.mjs --effective-date 2026-10-01 --operator "calshare運営事務局" --court "○○地方裁判所" --dry-run
   node scripts/legal/apply-legal-values.mjs --effective-date 2026-10-01 --operator "calshare運営事務局" --court "○○地方裁判所"
   ```

3. 次のコマンドで未記入のプレースホルダが残っていないことを確認する。

   ```sh
   node scripts/legal/checkLegalDocs.mjs --strict
   ```

   すべて `OK` で、`WARN`（プレースホルダ残存）が出なければ完了。`NG` や `WARN` が出た場合は「失敗したときの見方」を参照。

4. 条文の内容（法的な正しさ・design.mdとの整合）は、`.claude/skills/legal-review`（存在する場合）を使って審査する。
5. 審査結果を読んだ上で、内容に問題が無ければPRを作成する。オーナーに残る判断は、値の決定（手順1）と、審査結果を読んだ上での承認（本手順）だけです。

## 判断が必要な事項（法的助言ではありません。必要に応じて専門家にご相談ください）

- **運営者表記**: 個人名を出すか、屋号（「calshare運営事務局」等）で表記するか。
- **準拠法・管轄裁判所**: ドラフトは準拠法を日本法固定にしていますが、管轄裁判所は未記入です。どの裁判所を専属的合意管轄とするか（一般には運営者の住所地の管轄裁判所とすることが多いです）。
- **未成年の扱い**: 本サービスは年齢確認の仕組みを持たないため、「保護者の同意を得てご利用ください」という案内以上の強制力を持たせられません。この表現で足りるか、あるいは別の対応（利用そのものを推奨しない旨の記載等）にするか。
- **広告の記述**: ドラフトは「施行時点では広告を掲載していない。掲載する場合は規約を改定する」としています（docs/concept.md「非課金路線」・docs/design.md §14.1のAdSense関連リスクに整合）。実態と異なる場合は要修正。
- **開示・訂正・利用停止請求の受付窓口が無いことの受容**: 現状、通報フォーム（`/:id/report`）以外に問い合わせ窓口がありません。通報フォームは特定のページIDに対してのみ機能するため、「自分が保有される情報について問い合わせたい」という一般的な請求を受ける窓口が存在しません。この状態を維持するか、別途の問い合わせ手段（連絡用メールアドレス等）を用意するかを判断してください。
- **非表示にされた作成者の異議申し立て経路が無いことの受容**: 同様に、ページを非表示にされた作成者が異議を申し立てる手段が現状ありません。この状態を維持するか判断してください。
- **アクセスログの保存期間**: design.md に保存期間の規定が無いため、privacy.md はCloudflareのログ基盤の保持設定に依存する旨のみを記載しています。運営者が独自の保存期間を定める場合は、privacy.md 第6条5項を書き換えてください。

## 将来サイトに掲載する際の方針

- 内容の改定は、まず `docs/legal/*.md` に対して行い、変更履歴表に記録します。
- 静的サイト（`/terms` `/privacy` `/report-policy` 等のページ、または `/` からのリンク）へのHTML化・掲載は、実装コード（`src/web/` 等）が用意される後続PRで行います。掲載時は、Markdownの内容をそのまま転記し、二重管理を避けるため変更履歴の管理はMarkdown側に一本化します。本書の時点ではHTML側の実装は存在しないため、掲載PRの作成は後続タスクとして残します。
- 掲載用PRのレビュー観点: 条文の欠落・番号のずれが無いこと、未記入のプレースホルダが残っていないこと（いずれも `node scripts/legal/checkLegalDocs.mjs --strict` で確認できます）。

## 失敗したときの見方

- `node scripts/legal/checkLegalDocs.mjs --strict` が `NG` を出したファイルについて、続く行に検査に失敗した項目（条番号の欠番/重複・変更履歴表の不備・ファイル不在）が列挙されます。該当箇所を該当ファイルで直し、再実行してください。
- `WARN` が出た場合は、未記入のプレースホルダが残っています。`node scripts/legal/apply-legal-values.mjs` を実行（または再実行）してから、`--strict` で再確認してください。
- `node scripts/legal/apply-legal-values.mjs` が対象ファイルを見つけられない場合は `[skip]` と表示されます。ファイルパスを確認してください。書き込み前に必ず `--dry-run` で変更予定の行を確認してください。
- 使い方はそれぞれ `--help` で確認できます（`node scripts/legal/checkLegalDocs.mjs --help`、`node scripts/legal/apply-legal-values.mjs --help`）。
- CI等で機械的に結果を扱いたい場合は `node scripts/legal/checkLegalDocs.mjs --json` でJSON出力できます（`ok` フィールドが `false` なら失敗）。
- `checkLegalDocs.mjs` はファイルを読むだけで書き込みは行いません。失敗してもリポジトリの内容は変化しません。`apply-legal-values.mjs` は `--dry-run` を付けない限り対象ファイルを書き換えます。
